# cbackup

Extracts Confluence Cloud pages into portable Markdown as an
[Open Knowledge Format](https://github.com/GoogleCloudPlatform/open-knowledge-format)
bundle, for **migrating content to another platform**.

The priorities, in order:

1. **Fidelity** — content arrives intact. Tables keep their structure, macros
   are converted or flagged, nothing disappears silently.
2. **Completeness** — attachments come along, links are rewritten, and the
   quality gate fails the run if any page lost content.
3. **Triage** — the index tells you which pages are worth migrating and which
   are risky to convert, before you commit to anything.

Re-runs are byte-stable, which makes repeated extraction safe and cheap. That
also happens to make the output diffable, but see the note at the end: that is
a side effect, not the purpose.

## Setup

```bash
uv sync                       # add --extra enrich for stage 4
cp cbackup.toml.example cbackup.toml
```

Credentials come from the environment and are **never** read from
`cbackup.toml`:

```bash
export CONFLUENCE_BASE_URL=https://yoursite.atlassian.net/wiki
export CONFLUENCE_EMAIL=you@example.com
export CONFLUENCE_API_TOKEN=...        # id.atlassian.com -> API tokens
export ANTHROPIC_API_KEY=...           # only for `enrich`
```

## Use

`--root` accepts a browser URL, a space key, a folder id or a page id. Any
config key can be overridden by a flag; with `cbackup.toml` filled in, the
flags are optional.

```bash
cbackup index  --root 'https://site.atlassian.net/wiki/spaces/SE/folder/123/Docs'
cbackup export --root SE
cbackup gate                      # exit code 1 if any page lost content
```

| Stage | Produces |
|---|---|
| `index` | `out/index/<root>_<timestamp>.csv` — one row per page: provenance, view counts, and a structural census (tables, complex tables, macros) that shows which pages are risky to convert |
| `export` | `out/bundle/` — the OKF bundle mirroring the page tree, with `index.md` per level and attachments under `assets/` |
| `gate` | `out/gate/report.json` + `report.html` — structural comparison of source against output |
| `enrich` | OKF `description` and `tags` in frontmatter (opt-in, see below) |

`index` checkpoints after each page, so an interrupted crawl resumes rather
than restarting.

## Fidelity

GFM cannot express merged cells or block content inside a table cell. Those
tables are emitted as **HTML passthrough** (which Obsidian renders) instead of
being silently flattened; their contents are converted too, so no Confluence
markup leaks through. Panels become callouts, `code` becomes fenced blocks,
`expand` becomes `<details>`.

`toc`, `pagetree` and `children` are generated by Confluence at render time.
There is no source text to carry over, so they become a visible placeholder —
freezing a stale list or dropping them silently would both mislead.

Any macro the converter does not recognise leaves a marker and a gate flag.
**Nothing disappears quietly.**

## Quality gate

`cbackup gate` compares the storage format against the Markdown and exits
non-zero if a page lost content. Losses fail; gains do not, since one source
construct can legitimately render several ways.

Strict: table count, **complex** table count (so a merged-cell table flattened
to pipes is caught), and code blocks. Advisory: headings, images, links. It
also fails on leaked storage markup and broken asset links.

## LLM enrichment (opt-in)

Off by default. It sends page content to the Anthropic API and costs money, so
it requires **both** explicit enabling and an interactive confirmation:

```bash
cbackup enrich --enrich --select from-index --from-index out/index/SE_*.csv
```

```
  !!  LLM ENRICHMENT IS ENABLED
      model        : claude-haiku-4-5
      pages        : 12 (capped at max_pages=10)
      sends        : ~18,400 input tokens of page content
      est. cost    : ~$0.020
      Page content will be sent to the Anthropic API.
  Continue? [y/N]
```

`--yes` skips the prompt for automation; the notice still prints, and it
refuses to run unattended without it. `max_pages` is a hard per-run cap.
Results are cached on a content hash, so unchanged pages are never re-sent and
re-runs cost nothing.

This is the only place an LLM touches the pipeline. Page bodies are never
model-generated.

## Development

```bash
uv run pytest            # offline: no network, no credentials
uv run pytest -m live    # opt-in, hits the real API to catch drift
```

Tests use synthetic fixtures reproducing the structures found in real spaces
rather than copies of real pages, so no internal documentation is committed.

## Optional: version-controlling the bundle

Not needed for a migration, and safe to ignore. It matters only if you keep
extracting over time and want to see what changed between runs -- the export
is byte-stable, so a repository turns each run into a reviewable diff.

If you do, use a **private** repository separate from this tool, since a
typical space is a few hundred pages of internal documentation:

```bash
cbackup export --root SE --bundle-dir ../confluence-mirror
```

`cbackup` prints a one-line reminder when the bundle is not in a repository
and behaves identically either way.

## Notes

- Confluence exposes **no last-viewed timestamp**; the Analytics API returns
  aggregate counts only. Relevance uses view counts over 30/90-day windows.
- View counts are **not** written to frontmatter by default
  (`[output] include_usage`): they drift daily and would rewrite every page on
  every run. They live in the index CSV.
- `generated.at` carries the page's last edit, which is what OKF means by
  "when the meaningful change occurred" — and keeps output stable.
